## Compatibility and behavior review

- The frontend consumes the existing `/rectifications` and `/act` REST contracts. It uses the shared API client, so the existing actor header, response status handling and Spanish-facing workflow remain in force; no API payload or schema migration was introduced.
- Rectification rejects known-but-inapplicable criteria before any in-memory change. The enclosing HTTP unit of work still commits inspection, audit and outbox effects atomically.
- Published schema documents, inspection snapshots and issued certificate snapshots are not rewritten. New applicability cannot expose an uncovered published version; starting an uncovered legacy inspection and issuing a new certificate from an uncovered frozen inspection fail closed. Any already-issued historical certificate remains as stored; the isolated audit probes did not inspect or migrate a user's default database.
- Outbox rows retain their existing schema and retry limit. Sequence paging only bounds work per dispatch call; conditional failure updates preserve `DONE`. There is no new external delivery guarantee.
- Asset-row locking adds serialization without a migration. Assignment still performs the open-inspection check and insertion in one transaction, so losing requests roll back their associated audit writes.
- `DESIGN.md` now records the configured-zone date rule, version-by-version coverage checks, the outbox pass behavior, assignment row locking, and the frontend rectification/act and component-test coverage.

The prior browser setup error (`missing field sandboxPolicy`) remains a separate coverage limitation. jsdom component tests execute the four repaired UI paths but do not count as full packaged-browser workflow evidence. A first full `verify` attempt stopped in the core unit suite because three mocked-clock tests did not stub `today(Instant)`; the mock contract was updated, and the successful final full run is `V-STEP5`.
